#### 母题 1：现代 C++ 其他类型系统问题有哪些常见追问？（原题 3 条）

- c++ 的可变参数是怎么实现的
- 知道auto吗？使用auto有什么需要注意的？
- 比如使用auto推导从vactor中取出的变量，会有什么问题

##### 背诵答案

> C++ 的可变参数有两种实现。C 风格使用 `...`，调用方按照平台 ABI 把参数放到寄存器或栈中，函数通过 `va_list`、`va_arg` 等宏读取，但参数数量和类型依赖额外约定，类型不安全。C++11 更推荐可变参数模板，它通过参数包在编译期展开，能够保留类型信息，也可以配合完美转发减少拷贝。
>
> `auto` 是编译期类型推导，不是动态类型。它必须有初始化，默认按值推导，会去掉引用和顶层 `const`。例如 `vector<int> v` 中，`auto x = v[0]` 得到的是 `int`，会拷贝元素，修改 `x` 不会影响 `v`；如果想引用原元素，应写 `auto& x = v[0]`，只读可以写 `const auto&`。遍历 `vector` 时也是一样，直接写 `auto` 可能导致每个元素都被拷贝；另外扩容后原来的引用、指针和迭代器可能失效。

##### 简单解释

- C 风格可变参数依赖数量或格式字符串，例如 `printf`；可变参数模板依赖编译期参数包，安全性更好。
- `vector<T>::operator[]` 返回 `T&`，但 `auto x = v[0]` 会按值推导成 `T`，所以会产生拷贝；`auto&` 才会绑定到原元素。
- `vector` 要求元素连续存储，扩容时会申请新空间、搬移元素并释放旧空间，所以原来的引用、指针和迭代器还指向旧地址，就会失效。
- 常见触发场景是 `push_back`、`emplace_back`、`insert` 或 `reserve` 导致容量不足并重新分配；`erase` 也会使被删除元素及其后面的迭代器失效。
- 解决方法是提前 `reserve` 减少扩容，修改容器后重新获取引用、指针或迭代器，不要继续使用已经失效的对象；如果需要长期稳定的元素地址，应选择更合适的容器或间接存储。

- std\:move()移动语义是什么操作？
- 什么是右值引用？

- 移动语义 move作用

##### 背诵答案

1. **左值和右值**

   - 左值：有稳定身份、可以取地址的对象，例如有名字的变量。
   - 右值：临时对象或将亡值，例如函数返回的临时对象。
   - 左值引用主要绑定左值，右值引用 `T&&` 主要绑定右值，也可以绑定经过 `std::move` 转换的左值。

2. **为什么引入右值引用**

   - 主要为了支持移动语义和完美转发。
   - 移动语义不是重新拷贝数据，而是直接转移资源所有权，例如转移指针、缓冲区等，减少深拷贝。

3. **移动构造和 `std::move`**

   - 移动构造函数一般写成 `Class(Class&&)`。
   - 它可以接管原对象的资源，再把原对象置为有效但资源为空的状态。
   - `std::move` 本身不会移动数据，只是把对象转换成右值。
   - 真正的资源转移发生在移动构造函数或移动赋值运算符中。
   - 移动后的对象仍然可以析构和重新赋值，但不能依赖它原来的资源内容。

4. **完美转发**

   - 完美转发是指模板函数继续传递参数时，保持参数原来的左值或右值属性。
   - 它依靠转发引用 `T&&`、引用折叠和 `std::forward` 实现。
   - 因为具名的右值引用变量在函数内部是左值，所以需要使用 `std::forward<T>` 恢复原来的值类别。

5. **空类的特殊成员函数**

   - 默认构造函数
   - 析构函数
   - 拷贝构造函数
   - 拷贝赋值运算符
   - 移动构造函数
   - 移动赋值运算符

   移动构造和移动赋值是 C++11 引入的，是否由编译器隐式生成，还要看类中是否自定义了其他特殊成员函数。

6. **Lambda 中的移动语义**

   - 可以通过 `[p = std::move(p)]` 把资源转移到 Lambda 闭包中，避免拷贝。
   - 如果使用引用捕获，必须保证被引用对象的生命周期足够长，否则可能产生悬空引用。

##### 简单解释

- `std::move(x)` 可以理解为把 `x` 转换成 `T&&`，它只是类型转换。
- 引用折叠规则：

```text
T&  && -> T&
T&& &  -> T&
T&& && -> T&&
```

- 指针可以为空，也可以重新指向其他对象；引用必须初始化，之后不能重新绑定。

#### 母题 3：C++ 中 auto、decltype 和类型推导规则是什么？（原题 3 条）

- C++ auto推导规则
- C++ 模板类型推导是干嘛的？
- auto

##### 背诵答案

1. **`auto` 是什么**

   - `auto` 是编译期的类型推导，编译器根据初始化表达式推导出变量的实际类型。
   - 它不是动态类型，变量在编译后仍然是确定的静态类型。
   - 使用 `auto` 时必须初始化。

2. **`auto` 的推导规则**

   - `auto` 默认按值推导，会去掉引用和顶层 `const`。
   - `auto&` 可以保留引用，`const auto&` 适合只读引用。
   - `auto&&` 在类型推导中通常是转发引用，可以根据对象是左值还是右值进行推导。

   ```cpp
   const int a = 10;

   auto x = a;          // int，去掉顶层 const
   const auto& y = a;   // const int&，保留引用和 const
   ```

3. **`decltype` 是什么**

   - `decltype` 根据表达式推导类型，更强调保留表达式本身的类型、引用和 `const` 属性。
   - `decltype(x)` 中，如果 `x` 是未加括号的变量名，得到的是变量声明时的类型。
   - `decltype((x))` 按表达式的值类别推导：左值是 `T&`，将亡值是 `T&&`，纯右值是 `T`。

   ```cpp
   int x = 10;

   decltype(x) a = x;    // int
   decltype((x)) b = x;  // int&
   ```

4. **模板类型推导是干什么的**

   - 模板类型推导是编译器根据函数调用时传入的参数，自动推导模板参数 `T` 的类型。
   - 然后编译器根据不同的 `T` 实例化出对应的函数或类，从而实现泛型编程。
   - `auto` 的推导规则和函数模板的类型推导有很多相似之处。

5. **使用时的注意点**

   - `auto` 必须依赖初始化表达式，不能单独声明。
   - 如果类型中的 `const`、引用关系很重要，就不能直接使用裸的 `auto`。
   - `decltype` 更适合需要精确保留类型信息的泛型代码和返回值推导场景。

##### 简单解释

- `auto` 重点是：根据初始化表达式推导并创建变量类型。
- `decltype` 重点是：获取已有表达式的准确类型。
- 模板推导重点是：根据实参生成具体的函数或类。

```text
auto     = 推导并创建变量类型
decltype = 获取已有表达式类型
模板推导 = 根据实参生成具体函数或类
```

##### 背诵答案

1. **Lambda 是什么**
   - Lambda 是 C++11 引入的匿名函数，本质上是编译器生成的一个闭包对象。
   - 这个对象内部重载了 `operator()`，所以可以像函数一样调用。
   - 它的主要特点是可以捕获外部变量，适合回调、算法和异步任务。

2. **基本语法**

   ```cpp
   [捕获列表](参数列表) mutable -> 返回类型 {
       // 函数体
   };
   ```

   例如：

   ```cpp
   auto add = [](int a, int b) {
       return a + b;
   };
   ```

3. **捕获方式**
   - `[x]`：按值捕获，保存一份副本。
   - `[&x]`：按引用捕获，直接访问外部变量。
   - `[=]`：默认按值捕获。
   - `[&]`：默认按引用捕获。
   - `[this]`：捕获当前对象指针。
   - `[*this]`：C++17 后可以拷贝当前对象。
   - `[p = std::move(p)]`：初始化捕获，可以把资源移动到 Lambda 中。

4. **按值捕获和按引用捕获的区别**

   ```cpp
   int x = 10;

   auto f = [x]() mutable {
       x++;
   };                    // 修改的是副本，不影响外部 x

   auto g = [&x]() {
       x++;
   };                    // 修改的是外部 x
   ```

   按值捕获默认不能修改 Lambda 内部的副本，如果要修改需要加 `mutable`，但仍然不会影响外部变量。想修改外部变量，需要引用捕获，但要注意生命周期和线程安全。

5. **Lambda 的底层实现**
   - 编译器会生成一个匿名类。
   - 按值捕获的变量会变成这个类的成员变量副本。
   - 按引用捕获的变量会保存对外部对象的引用。
   - Lambda 的调用操作会转换成这个匿名类的 `operator()`。

6. **使用 Lambda 创建线程时的注意点**
   - Lambda 使用引用捕获时，保存的只是局部变量的引用，不会延长局部变量的生命周期。
   - 如果 Lambda 启动了新线程，线程的执行时间是不确定的。外层函数可能已经返回，局部变量也已经销毁，但新线程还在访问它，就会产生悬空引用和未定义行为。

   ```cpp
   void func() {
       int value = 10;

       std::thread t([&value]() {
           std::cout << value << std::endl;
       });

       t.join();  // 等线程执行完，引用才安全
   }
   ```

   - 如果使用 `detach()`，函数返回后局部变量可能已经销毁，线程继续访问该变量就是不安全的。
   - 解决方法是使用 `join()`，或者改用值捕获 `[value]`；对不可拷贝资源，可以使用 `[p = std::move(p)]`。
   - 多线程共享数据时，还需要使用互斥锁或原子变量保证线程安全。
   - 捕获 `this` 时也要注意对象生命周期，如果线程执行时对象已经析构，同样会产生悬空指针。

7. **Lambda 和普通函数的区别**
   - 普通函数有名字，不能直接保存局部状态。
   - Lambda 没有名字，但可以捕获外部变量，形成带状态的闭包对象。
   - 不捕获变量的 Lambda 通常可以转换成函数指针；捕获变量的 Lambda 一般不能直接转换成普通函数指针。
   - Lambda 常用于 `sort`、`for_each`、回调函数和异步任务。

##### 简单解释

- Lambda 的本质：**匿名函数 + 捕获状态 + 闭包对象**。
- 按值捕获：安全，但会产生副本；使用 `mutable` 修改的也是副本。
- 按引用捕获：避免拷贝，也能修改外部变量，但必须保证生命周期安全。
- 异步场景中，引用捕获的局部变量可能在线程执行前销毁；应使用 `join()`、值捕获或移动捕获解决。

#### 母题 5：C++ 的类型转换有哪些？安全性如何？（原题 6 条）

- C++的类型转换函数有哪些
- C++ 的四种类型转换
- 四种类型转换
- std::variant，union 怎么知道参数类型？
- 类型转换安全性
- 强转是重新解释布局内存还是复制或者构造

##### 背诵答案

1. **C++ 四种类型转换及案例**

   - **`static_cast`：编译期常规转换**

     ```cpp
     double d = 3.14;
     int i = static_cast<int>(d);  // 数值转换，i 为 3
     ```

     也可以用于父子类转换。子类转父类通常安全，但父类指针向子类指针转换时，`static_cast` 不会进行运行时检查，类型错误可能导致未定义行为。

   - **`const_cast`：去掉 `const` 或 `volatile`**

     ```cpp
     const int value = 10;
     int* p = const_cast<int*>(&value);
     ```

     它只是去掉类型上的 `const`。如果对象本身确实是 `const`，再通过 `p` 修改它就是未定义行为。

   - **`reinterpret_cast`：重新解释地址或内存**

     ```cpp
     int value = 10;
     int* p = &value;
     std::uintptr_t address = reinterpret_cast<std::uintptr_t>(p);
     ```

     它不会真正转换对象，只是把地址或内存按照另一种类型解释，常见于底层编程，但要注意对齐、对象生命周期和类型别名规则，风险较大。

   - **`dynamic_cast`：运行时安全检查**

     ```cpp
     struct Base {
         virtual ~Base() = default;
     };

     struct Derived : Base {};

     Base* base = new Derived;
     Derived* derived = dynamic_cast<Derived*>(base);
     ```

     如果实际对象是 `Derived`，转换成功；如果类型不匹配，指针转换返回 `nullptr`，引用转换会抛出 `std::bad_cast`。基类通常需要有虚函数。

2. **`std::variant` 和 `union` 如何知道当前类型**

   - `std::variant` 可以理解为带类型标签的安全联合体。它内部保存一块能够容纳所有候选类型的存储空间，同时保存一个索引，表示当前激活的是哪一种类型。
   - 访问时可以使用 `std::get`、`std::get_if` 或 `std::holds_alternative`。类型不匹配时，`std::get` 会抛出 `std::bad_variant_access`，`std::get_if` 返回空指针。
   - `union` 只是让多个成员共享同一块内存，本身不保存当前活动成员。程序员需要自己记录当前类型；如果读取了非当前活动成员，通常会产生未定义行为，复杂对象还需要手动管理构造和析构。

3. **强制类型转换是复制、构造还是重新解释**

   - 数值类型转换通常会计算并生成一个新的目标类型值，例如 `double` 转 `int`。
   - 类类型转换可能调用目标类的构造函数或类型转换运算符，因此可能产生新对象。
   - 指针或引用转换一般只调整指针类型或地址，不会复制指向的对象。
   - `const_cast` 只改变类型限定，不复制对象；`reinterpret_cast` 重新解释地址或位模式，也不负责构造新对象；`dynamic_cast` 进行运行时类型检查和指针调整，不会复制原对象。

##### 简单解释

- `static_cast`：普通转换，编译期完成。
- `const_cast`：修改 `const` 属性，但不能因此修改真正的常量对象。
- `reinterpret_cast`：重新解释地址或内存，风险最大。
- `dynamic_cast`：运行时检查类层次关系。
- `variant`：保存当前类型索引，访问更安全；`union`：只共享内存，不自动记录当前类型。

#### 母题 6：C++11 / C++20 等现代 C++ 新特性怎么理解？（原题 9 条）

##### 背诵答案

1. **C++11 主要新特性**

   - `auto`、`nullptr`、范围 `for` 循环和 Lambda；
   - 右值引用、移动语义和完美转发；
   - `unique_ptr`、`shared_ptr` 等智能指针；
   - 可变参数模板、`constexpr`、`enum class`；
   - `std::thread`、互斥锁、原子变量、条件变量和 `chrono`；
   - `override`、`final`、初始化列表等。

   C++11 的核心变化可以概括为：**增强类型推导、资源管理、泛型编程和并发编程能力。**

2. **`QThread` 和 `std::thread` 的区别**

   - `std::thread` 是 C++ 标准库提供的线程封装，跨平台性好，但本身不提供 Qt 的事件循环、信号槽等机制。
   - `QThread` 是 Qt 的线程类，可以和 `QObject`、信号槽、事件循环结合，适合 Qt 应用中的异步任务。
   - `std::thread` 通常配合 `mutex`、`condition_variable` 等标准库工具使用；`QThread` 通常配合 Qt 的信号槽和 `moveToThread` 使用。
   - 如果是 Qt 项目，我会优先考虑 `QThread`；如果只需要标准 C++ 线程能力，可以使用 `std::thread`。

3. **`const` 和 `mutable`**

   - `const` 表示对象或成员函数不能修改对象状态。
   - `mutable` 可以修饰成员变量，使它能够在 `const` 成员函数中被修改，常用于缓存、统计信息或互斥锁等不影响逻辑状态的成员。
   - Lambda 中的 `mutable` 含义不同，它允许修改按值捕获的变量副本，但不会修改外部变量。

4. **C++20 Ranges 和 View**

   - Ranges 提供了一套面向范围的算法，可以直接对容器或区间进行操作，减少迭代器样板代码。
   - View 是对数据范围的一个轻量级、非拥有的视图，通常采用惰性计算，不会立即生成新的容器。
   - 多个 View 可以通过管道组合，例如先过滤，再转换，最后遍历。
   - 使用 View 时要注意底层数据的生命周期，因为 View 通常不负责保存数据。

5. **C++20 其他新特性**

   - `concepts`：约束模板参数，让模板错误更容易理解；
   - `ranges`：提供范围和惰性视图；
   - 协程：支持函数暂停和恢复；
   - `modules`：改进头文件和编译依赖；
   - 三路比较运算符 `<=>`：简化比较运算符的定义。

6. **C++20 协程**

   - 协程是一种可以暂停和恢复执行的函数。
   - 通过 `co_await`、`co_yield` 和 `co_return` 控制异步等待、产生数据和返回结果。
   - 编译器会把协程转换成类似状态机的结构，保存局部状态，在之后恢复执行。
   - 协程本身不等于线程，也不会自动创建线程，具体由事件循环或调度器决定。
   - 它适合异步 IO、网络请求、任务流水线和生成器等场景。

##### 简单解释

- C++11 重点记忆：**Lambda、智能指针、移动语义、可变参数模板、线程库**。
- `QThread` 偏 Qt 生态，支持事件循环和信号槽；`std::thread` 偏标准 C++，更加通用。
- `const` 表示通常不能修改，`mutable` 表示允许修改某些特殊状态。
- Ranges 负责更方便地操作范围，View 负责以惰性方式组织数据。
- 协程的核心是：**可以暂停和恢复，但不等于创建新线程**。

##### 背诵答案

1. **模板和泛型是什么**

   - 模板是 C++ 实现泛型编程的主要机制。
   - 它把类型或数值作为参数，让同一份代码适用于不同类型。
   - 模板在编译期实例化，不是运行时动态生成，所以既有类型安全，也不会额外产生运行时分派开销。

2. **用模板实现加法函数**

   ```cpp
   template <typename T>
   T add(T a, T b) {
       return a + b;
   }
   ```

   调用 `add(1, 2)` 时，编译器会推导出 `T` 是 `int`；调用 `add(1.0, 2.0)` 时，`T` 就是 `double`，然后分别生成对应的函数。

3. **模板函数会在 bin 文件中生成几份**

   - 通常是每使用一种具体类型，就会实例化一份对应代码。
   - 比如 `add<int>` 和 `add<double>` 通常会生成两种特化版本。
   - 但最终二进制中是否完全保留多份，还会受到编译器优化、链接器合并和是否真正使用的影响，所以不能简单说模板函数固定生成一份或多份。

4. **CRTP 是什么**

   CRTP 是“奇异递归模板模式”，让子类把自己的类型传给基类：

   ```cpp
   template <typename Derived>
   class Base {
   public:
       void run() {
           static_cast<Derived*>(this)->process();
       }
   };

   class Child : public Base<Child> {
   public:
       void process() {}
   };
   ```

   它通过模板在编译期确定调用对象，实现静态多态，不需要虚函数表和运行时虚函数调用。缺点是类型在编译期就确定了，不能像虚函数那样运行时替换对象，并且可能增加代码体积。

5. **模板元编程是什么**

   - 模板元编程是利用模板和类型系统在编译期进行计算或生成代码。
   - 常见用途包括类型萃取、条件判断、编译期计算、泛型约束等。
   - 现在通常还会结合 `constexpr`、`type_traits` 和 `concepts` 使用。
   - 模板本身主要在编译期实现泛型，但模板实例化后的普通函数，仍然是在运行时执行。

6. **抽象接口如何实现模块解耦**

   - 抽象接口不是一个全局类，而是只定义模块之间约定的能力。
   - 例如支付模块可以定义 `IPayment` 接口，具体实现有支付宝、微信支付和银联支付。
   - 上层订单模块只依赖 `IPayment`，不直接依赖具体支付类；具体实现通过工厂、配置或依赖注入传入。
   - 如果希望运行时切换实现，可以使用虚函数接口；如果类型在编译期确定，也可以使用模板或 CRTP。

7. **多个支付渠道如何设计**

   - 我会以**策略模式 + 工厂模式**为主。
   - 把支付宝、微信和银联分别实现成支付策略，统一提供支付、退款、查询等接口。
   - 工厂根据支付渠道或配置创建对应的策略对象，订单模块只调用统一接口。
   - 如果所有渠道都有固定流程，比如参数校验、下单、记录日志、结果通知，可以抽取公共流程；如果还存在不同平台和不同支付渠道的两个独立变化维度，可以进一步考虑桥接模式。

8. **泛型通常使用在哪些场景**

   - STL 容器和算法，例如 `vector<T>`、`sort`；
   - 通用数据结构和工具函数；
   - 需要支持多种数据类型，但处理逻辑基本相同的场景；
   - 对性能要求较高、不希望使用运行时多态的场景。

##### 简单解释

- 模板：**写一份代码，编译期生成不同类型的版本**。
- 泛型：**让算法和数据结构不依赖某一种具体类型**。
- CRTP：**用模板实现编译期多态**。
- 模板元编程：**在编译期做类型计算或代码生成**。
- 支付设计：**策略负责不同支付实现，工厂负责创建，订单模块依赖抽象接口**。

##### 背诵答案

1. **智能指针是什么**

   智能指针是对原始指针的 RAII 封装，通过对象生命周期自动管理堆内存，避免忘记 `delete`。C++11 主要提供三种：

   - `unique_ptr`：独占所有权，不能拷贝，只能移动。
   - `shared_ptr`：共享所有权，通过引用计数管理对象。
   - `weak_ptr`：弱引用，不增加强引用计数，主要用于观察对象和解决循环引用。

2. **`shared_ptr` 如何构造**

   通常优先使用：

   ```cpp
   auto p = std::make_shared<T>(args...);
   ```

   它通常只需要一次内存分配，写法也更安全。

   也可以使用：

   ```cpp
   std::shared_ptr<T> p(new T);
   ```

   这种写法本身是合法的，但要避免同一个原始指针被多个 `shared_ptr` 分别管理：

   ```cpp
   T* raw = new T;
   std::shared_ptr<T> p1(raw);
   std::shared_ptr<T> p2(raw); // 错误：可能导致重复释放
   ```

3. **`shared_ptr` 的内存管理机制**

   `shared_ptr` 通常包含对象指针、控制块、强引用计数、弱引用计数和删除器等信息。复制 `shared_ptr` 时，强引用计数加一；销毁时减一。当强引用计数为零时，释放实际对象；当弱引用也全部消失后，再释放控制块。

4. **为什么需要 `weak_ptr`**

   `weak_ptr` 不拥有对象，不增加强引用计数，可以通过 `lock()` 临时获取一个 `shared_ptr`：

   ```cpp
   auto p = weak.lock();
   if (p) {
       // 对象仍然存在
   }
   ```

   它最主要的作用是解决循环引用：

   ```cpp
   struct A {
       std::shared_ptr<B> b;
   };

   struct B {
       std::weak_ptr<A> a;
   };
   ```

   如果 `A` 和 `B` 都使用 `shared_ptr` 互相引用，即使外部引用释放，双方的引用计数仍不为零，就会导致内存泄漏。

5. **智能指针有哪些风险**

   - `shared_ptr` 循环引用导致内存泄漏；
   - 同一个原始指针被多个 `shared_ptr` 管理，导致重复释放；
   - 保存了 `get()` 返回的原始指针，智能指针释放后原始指针悬空；
   - 滥用 `shared_ptr`，造成不必要的引用计数和控制块开销；
   - 智能指针本身线程安全，不代表它管理的对象可以被多个线程同时修改。

6. **多线程下是否安全**

   多个不同的 `shared_ptr` 实例，即使共享同一个控制块，引用计数的增加和减少通常是线程安全的。

   但是，同一个 `shared_ptr` 对象被一个线程读取、另一个线程同时修改，不能直接认为是安全的，需要加锁，或者使用 `std::atomic<std::shared_ptr<T>>`。

   另外，对同一个被管理对象进行并发读写，仍然需要互斥锁或原子变量保护。

7. **如何实现一个简化版 `shared_ptr`**

   核心是控制块和引用计数：

   - 控制块保存原始指针、强引用计数和弱引用计数；
   - 拷贝构造时增加强引用计数；
   - 析构时减少强引用计数；
   - 强引用计数变为零时释放对象；
   - 弱引用计数也变为零时释放控制块；
   - `weak_ptr::lock()` 需要在对象未释放时安全地增加强引用计数。

8. **实际使用中的选型**

   实际开发中，一般优先使用 `make_unique` 或 `make_shared`；只有确实需要共享所有权时才使用 `shared_ptr`，对象关系中的反向引用通常使用 `weak_ptr`。

##### 简单解释

- `unique_ptr`：一个人独占资源。
- `shared_ptr`：多人共同拥有资源。
- `weak_ptr`：只观察资源，不负责延长资源生命周期。
- 智能指针的核心是自动管理所有权和生命周期，但它不能自动保证业务对象的线程安全。

##### 背诵答案

1. **智能指针是什么**

   智能指针是对原始指针的 RAII 封装，通过对象生命周期自动释放堆内存，减少内存泄漏、野指针和重复释放问题。C++11 常用的有 `unique_ptr`、`shared_ptr` 和 `weak_ptr`。

2. **三种智能指针的区别**

   - `unique_ptr`：独占所有权，不能拷贝，只能移动。适合一个对象只有一个管理者的场景。
   - `shared_ptr`：共享所有权，多个指针通过控制块和引用计数共同管理对象。适合多个模块共同持有对象。
   - `weak_ptr`：不拥有对象，不增加强引用计数，必须通过 `lock()` 临时获取 `shared_ptr`。主要用于解决循环引用和观察对象。

   以前还有 `auto_ptr`，但它存在拷贝后所有权转移等问题，已经被废弃，不应该在新代码中使用。

3. **智能指针解决什么问题**

   它主要解决手动 `new/delete` 带来的生命周期管理问题。例如函数中途抛异常或提前返回时，RAII 可以保证对象自动释放。

4. **智能指针的核心区别**

   核心区别是所有权模型不同：

   - `unique_ptr` 是独占所有权；
   - `shared_ptr` 是共享所有权；
   - `weak_ptr` 不参与所有权，只负责观察。

   实际开发中优先使用 `unique_ptr`，确实需要共享所有权时再使用 `shared_ptr`。

5. **父类智能指针如何管理派生类对象**

   可以让 `shared_ptr<Base>` 指向派生类对象：

   ```cpp
   struct Base {
       virtual ~Base() = default;
       virtual void run() = 0;
   };

   struct Derived : Base {
       void run() override {}
   };

   std::shared_ptr<Base> p = std::make_shared<Derived>();
   p->run();
   ```

   这里通过虚函数实现多态，调用时不需要知道具体派生类。父类析构函数必须是虚函数，保证通过父类指针释放派生类对象时正确析构。如果确实需要转换为具体派生类，可以使用 `std::dynamic_pointer_cast<Derived>(p)`。

6. **如何解决循环引用**

   如果两个对象互相使用 `shared_ptr`，双方引用计数都无法归零，就会造成内存泄漏。通常把其中一个方向改成 `weak_ptr`，打破所有权环。

7. **智能指针是否线程安全**

   不同的 `shared_ptr` 实例共享同一个控制块时，引用计数的增减通常是线程安全的。

   但是，同一个 `shared_ptr` 对象被多个线程同时读写并不安全，需要加锁，或者使用原子智能指针。同时，智能指针线程安全不代表它管理的对象可以被多个线程同时修改，对象本身仍然需要锁或原子操作保护。

8. **实际使用场景和选型**

   - 独占资源、明确唯一管理者：使用 `unique_ptr`；
   - 多个模块需要共同延长对象生命周期：使用 `shared_ptr`；
   - 父子对象、观察者、缓存和回调中的反向引用：使用 `weak_ptr`；
   - 多态对象可以用 `shared_ptr<Base>` 统一管理，通过虚函数调用派生类行为。

##### 简单解释

- `unique_ptr`：一个人负责资源。
- `shared_ptr`：多人共同负责资源。
- `weak_ptr`：只观察资源，不负责释放。
- 选型时遵循：能用 `unique_ptr` 就不用 `shared_ptr`，需要打破循环引用就使用 `weak_ptr`。
